02 · Architecture

The IPO model

Every run follows the same three-stage shape, once for encryption and once — in reverse — for decryption.

INPUT

Plaintext + key

Raw user text, plus an integer shift value the user chooses.

→
PROCESS

Caesar shift

Each letter is converted to a number, shifted, and wrapped with % 26.

→
OUTPUT

Ciphertext

Unreadable text that only someone with the key can reverse.

plaintext→ ord(char)→ + shift→ % 26→ chr(...)→ ciphertext

What's included

Every DecodeLabs deliverable, in one build

Encrypt & decrypt functions

Two small, reusable functions — encrypt(text, shift) and decrypt(text, shift) — plus a validate_shift() helper.

ASCII math, in the open

Built on ord(), chr(), and modulo 26 — no external cryptography library, so the logic stays visible.

Edge cases handled

Spaces, punctuation, digits, and symbols pass through unchanged; only letters are shifted, and case is preserved.

User-defined key

Any integer works. Values above 26 or below 0 are normalized automatically — 29 behaves exactly like 3.

Round-trip validation

Every run proves decrypt(encrypt(text, shift), shift) == text, with 17 automated tests behind it.

Honest about its limits

Documents exactly why a Caesar cipher isn't real security — brute force and frequency analysis, explained below.

03 · The math

From letter to number and back

Computers don't store "A" — they store 65. Encryption does its work entirely in that numeric space, then converts back to a letter at the very end.

    05 · Security reality check

    Why this isn't real protection

    A Caesar cipher demonstrates the idea of encryption — it should never guard anything actually sensitive. Two weaknesses explain why.

    Weakness 01

    Tiny key space

    There are only 25 meaningful shifts. A computer — or a patient person — can try every single one in well under a second and simply read off the one that makes sense.

    Weakness 02

    Pattern preservation

    Shifting doesn't change how often each letter appears — just its name. Since "E" is common in English, frequency analysis can spot the shift without even trying all 25.

    Caesar cipher

    Fixed shift, 25 possible keys. Built here to teach the fundamentals.

    Modern cryptography

    Confusion and diffusion make the key–ciphertext relationship far harder to trace.

    AES

    128-bit+ keys and multiple XOR-based rounds — the standard for real-world confidentiality.
